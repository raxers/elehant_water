# Протокол Bluetooth-счётчиков Элехант

Описание формата Bluetooth-объявлений счётчиков газа, воды, электричества и
тепла Элехант, а также шлюза WiFi box.

Формат сверен с разбором пакетов в официальном приложении «Элехант Счётчики»
для Android (`ru.elehant.homecounters`, версия 5.0.5) и с реальными
счётчиками. Первые сведения собраны сообществом:
[vooon/elehant-to-mqtt](https://github.com/vooon/elehant-to-mqtt/blob/master/docs/protocol.md).
Реализация в этом репозитории — [`parser.py`](../custom_components/elehant_water/parser.py).

Все многобайтовые числа — little endian, если не сказано иное. Байты пакета
нумеруются с нуля.

## Передача данных

- Счётчики не принимают соединений и не используют GATT. Все данные
  передаются только в BLE-объявлениях (advertising).
- Данные лежат в поле Manufacturer Specific Data (тип AD `0xFF`) с
  идентификатором производителя **`0xFFFF`**. Официального идентификатора
  Bluetooth SIG у Элехант нет, `0xFFFF` зарезервирован для тестов, поэтому
  его используют и другие устройства.
- После двух байт идентификатора идут **17 байт** данных. Вместе с
  идентификатором поле занимает 19 байт, запись AD целиком — `14 FF FF FF …`.
- Счётчики вещают раз в несколько секунд. СВД-15, например, — примерно раз
  в 16 секунд.

Дальше «пакет» — это 17 байт данных **без** идентификатора производителя.
В таком виде их отдают Home Assistant (`manufacturer_data[65535]`), ESPHome и
большинство BLE-библиотек.

## Адрес устройства

Адрес содержит всё, что нужно для идентификации счётчика:

```
B0 : 01 : 02 : 01 1F 59
│    │    │    └──────── серийный номер, 3 байта, big endian (0x011F59 = 73561)
│    │    └───────────── тип счётчика
│    └────────────────── модель
└─────────────────────── префикс
```

| Префикс | Назначение |
|---------|------------|
| `B0` | Открытые пакеты с показаниями |
| `C0` | Тоже открытые пакеты, приложение разбирает их так же, как `B0` |
| `B1` | Зашифрованные пакеты. Приложение их не расшифровывает, а отправляет на сервер Элехант. У счётчиков, которые вещают с `B1`, обычно есть и адрес `B0` с тем же номером |

Счётчик может вещать с нескольких адресов одновременно, например `B0:…` и
`B1:…` с одним серийным номером. Двухтарифные счётчики воды, передающие
пакеты версии 1, вещают каждый тариф со своего адреса (своя модель, один
номер), см. [модели](#модели).

Тип, модель и серийный номер из адреса повторяются в [заголовке](#общий-заголовок)
пакета. Приложение на Android отбрасывает пакет, если они не совпадают. На iOS
MAC-адрес недоступен, и приложение эту проверку пропускает.

## Газ, вода, тепло: версия 1

Основной формат газовых, водяных и теплосчётчиков.

| Байт | Размер | Значение |
|------|--------|----------|
| 0 | 1 | Флаги, см. [заголовок](#общий-заголовок) |
| 1 | 1 | Не используется приложением. По наблюдениям — счётчик пакетов, растёт на 1 с каждым объявлением |
| 2 | 1 | Младшая тетрада (`& 0x0F`) — дополнительный разряд показаний при флаге `0x04`. Старшая тетрада не используется |
| 3 | 1 | `0x01` |
| 4–8 | 5 | Тип, модель, серийный номер |
| 9–12 | 4 | Показания, беззнаковое, в десятитысячных единицы |
| 13 | 1 | Заряд батареи, см. [заряд батареи](#заряд-батареи) (граница 171) |
| 14–15 | 2 | Температура, **знаковое**, в сотых °C. Действительна не у всех моделей, см. [температура](#температура) |
| 16 | 1 | Версия прошивки, в десятых (`0x21` = 33 = 3.3) |

**Показания:**

```
raw = u32(байты 9–12)
если байт0 & 0x04:
    raw = raw + (байт2 & 0x0F) / 10
значение = raw / 10000
```

Единица измерения зависит от типа:

| Тип | Единица | Шаг без флага `0x04` | Шаг с флагом `0x04` |
|-----|---------|----------------------|---------------------|
| Газ | м³ | 0,0001 м³ (0,1 л) | 0,00001 м³ (0,01 л) |
| Вода | м³ | 0,0001 м³ (0,1 л) | 0,00001 м³ (0,01 л) |
| Тепло | ГДж | 0,0001 ГДж | 0,00001 ГДж |

## Двухтарифная вода: версия 5

Двухтарифный счётчик воды передаёт оба тарифа в одном пакете с разрешением
1 литр. Разбирается только для воды.

| Байт | Размер | Значение |
|------|--------|----------|
| 0 | 1 | Флаги |
| 1 | 1 | Заряд батареи, см. [заряд батареи](#заряд-батареи) (граница **127**) |
| 2 | 1 | Температура, беззнаковое, **целые** °C |
| 3 | 1 | `0x05` |
| 4–8 | 5 | Тип, модель, серийный номер |
| 9 | 1 | Старшая тетрада — старшие 4 бита первого показания, младшая тетрада — старшие 4 бита второго |
| 10–12 | 3 | Младшие 24 бита первого показания, **big endian** |
| 13–15 | 3 | Младшие 24 бита второго показания, **big endian** |
| 16 | 1 | Версия прошивки, в десятых |

```
первое = ((байт9 >> 4) << 24) | (байт10 << 16) | (байт11 << 8) | байт12
второе = ((байт9 & 0x0F) << 24) | (байт13 << 16) | (байт14 << 8) | байт15
показания, м³ = первое / 1000, второе / 1000
```

Показания 28-битные, максимум 268 435,455 м³.

**Какое показание к какому тарифу относится.** Первое показание принадлежит
модели из заголовка пакета, второе — парной модели того же счётчика (модель
±1, см. [модели](#модели)). Например, для пакета с адреса `B0:04:02:…` (СВТ-15,
тариф 1) первое показание — тариф 1, второе — тариф 2. Для пакета с
`B0:03:02:…` — наоборот.

## Электричество

Электросчётчики (тип 3) по очереди передают пакеты разных версий, каждый со
своим набором величин. Полную картину даёт только набор пакетов, собранный за
некоторое время. Батареи, прошивки и температуры для отображения в этих
пакетах нет.

Обозначения: `A = u32(байты 9–12)`, `B = u32(байты 13–16)`,
`u16(n) = u16(байты n, n+1)`.

| Версия | Величины |
|--------|----------|
| 0 | Активная энергия А+ (импорт) = `A / 1000` кВт·ч; активная энергия А− (экспорт) = `B / 1000` кВт·ч |
| 1–4 | То же для тарифа с номером версии: А+ тариф N = `A / 1000`, А− тариф N = `B / 1000` кВт·ч |
| 16 | Реактивная энергия R+ = `A / 1000` квар·ч; R− = `B / 1000` квар·ч |
| 17–20 | То же для тарифа N = версия − 16 |
| 32 | Однофазная сеть: напряжение = `u16(9) / 10` В; ток фазы = `u16(11) / 100` А; ток нейтрали = `u16(13) / 100` А; дифференциальный ток = `u16(15) / 100` А |
| 33 | Трёхфазная сеть: напряжения фаз A, B, C = `u16(9)`, `u16(11)`, `u16(13)`, делённые на 10, В |
| 34 | Трёхфазная сеть: линейные напряжения = `u16(9)`, `u16(11)`, `u16(13)`, делённые на 10, В. Порядок, вероятно, AB, BC, CA (см. [что неизвестно](#что-неизвестно)) |
| 35 | Трёхфазная сеть: токи фаз A, B, C = `u16(9)`, `u16(11)`, `u16(13)`, делённые на 100, А; ток нейтрали = `u16(15) / 100` А |
| 48 | Полная мощность = `A / 100` В·А; частота = `u16(13) / 100` Гц; коэффициент мощности (cos φ) = `байт15 / 100`; байт 16 — температура, целые °C (приложение её сохраняет, но не показывает) |
| 49 | Активная мощность = `A / 100` Вт; реактивная мощность = `B / 100` вар |
| прочие | Игнорируются |

Буква «P» в названиях реактивной энергии в приложении (`EnPPSum`, «Энергия
P+») — это кириллическая «Р», реактивная энергия.

## Заряд батареи

Приложение преобразует байт батареи так:

```
если raw < 1 или raw > граница: заряд = 1 %
иначе если raw > 100:            заряд = 100 %
иначе:                            заряд = raw %
```

Граница — **171** для версии 1 и WiFi box, **127** для версии 5.

- Значения 101…граница встречаются на реальных счётчиках (например, 101, 103
  и 127) и показываются как 100%.
- Иконка батареи в приложении имеет три состояния: полная (больше 60%),
  наполовину (21–60%) и пустая (20% и меньше). Поэтому у счётчика с зарядом
  63% иконка в приложении полная.
- У электросчётчиков заряд батареи не показывается.

## Температура

Поле температуры есть во всех пакетах версий 1 и 5, но значение имеет не у
всех моделей. У газовых счётчиков в нём мусор: на реальных счётчиках
встречаются −99,8 °C и 40,5 °C.

Правило приложения: у каждой модели задан признак «показывать температуру» и
список прошивок-исключений. Для прошивок из списка признак инвертируется.

| СВД-20 | да | нет у 1.4, 1.6, 1.7, 1.8, 1.9 |
| СВТ-15, СВТ-20, СВТУ-15, СВТУ-20, TWM-15, TWM-20 | да | — |
| СВДУ-15, СВДУ-20, SWTU-15, SWTU-20 | нет | — |
| Электричество | нет | — |

## Модели

«Пара» — модель, передающая второй тариф того же двухтарифного счётчика.
«Тариф» — какой тариф передаёт модель (в приложении — порядок отображения).
Счётчик в паре определяется по модели с тарифом 1.

«Прошивки» — список версий прошивки, с которыми приложение принимает пакеты.
Приложение обновляет этот список с сервера, так что он может быть неполным.
Версии с двумя знаками после запятой (например, 1.11) в пакете версии 1
передать нельзя (байт в десятых); вероятно, они приходят с сервера.

## Проверка пакета в приложении

Приложение принимает пакет с показаниями, только если:

1. установлен бит `0x80` в байте 0 (проверяется в разборе версий 1, 5,
   электросчётчиков и WiFi box);
2. префикс адреса `B0` или `C0`, а тип, модель и серийный номер в адресе
   совпадают с заголовком (кроме iOS);
3. серийный номер больше нуля;
4. показания не отрицательные;
5. тип и модель есть в [таблице моделей](#модели), а версия прошивки — в списке
   для этой модели.

Пункты 3–5 проверяются для версий 1 и 5, электросчётчиков и WiFi box. Пакеты
версии 9 принимаются без них, пакеты версии 8 не считаются показаниями.

Пакеты с префиксом `B1` приложение не разбирает. Оно лишь проверяет, что тип и
модель из адреса известны, и отправляет пакет на сервер.

Интеграция в этом репозитории проверяет пункты 1–3 и 5, но **не** проверяет
версию прошивки: иначе счётчики с новой прошивкой перестали бы работать до
обновления интеграции.

## Примеры разбора

### СВД-15, версия 1

Реальный пакет, серийный номер заменён на 12345. Приложение показывает для
этого счётчика заряд 63%.

```
80 3A 96 01 02 01 39 30 00 F2 40 18 00 3F 90 08 21
```

| Байты | Значение | Разбор |
|-------|----------|--------|
| `80` | флаги | действительный пакет, обычная точность |
| `3A` | 58 | счётчик пакетов |
| `96` | — | не используется (флаг `0x04` не установлен) |
| `01` | версия 1 | |
| `02 01` | вода, модель 1 | СВД-15 |
| `39 30 00` | 0x003039 | серийный номер 12345 |
| `F2 40 18 00` | 0x001840F2 = 1 589 490 | 158,949 м³ |
| `3F` | 63 | заряд 63% |
| `90 08` | 0x0890 = 2192 | 21,92 °C (у СВД-15 с прошивкой 3.3 температура есть) |
| `21` | 33 | прошивка 3.3 |

### СГБД-4.0, версия 1

Реальный пакет из [issue](https://github.com/raxers/elehant_water/issues),
адрес `B0:12:01:00:05:55`.

```
80 06 0A 01 01 12 55 05 00 A1 F3 35 00 67 04 D9 0B
```

| Байты | Значение | Разбор |
|-------|----------|--------|
| `01 12` | газ, модель 18 | СГБД-4.0 |
| `55 05 00` | 0x000555 | серийный номер 1365 |
| `A1 F3 35 00` | 3 535 777 | 353,5777 м³ |
| `67` | 103 | заряд 100% (103 > 100) |
| `04 D9` | −9980 | −99,80 °C — мусор, у газовых счётчиков температуры нет |
| `0B` | 11 | прошивка 1.1 |

### СВТ-15, версия 5

Пакет с адреса `B0:04:02:00:12:34` (модель 4 — тариф 1):

```
80 57 18 05 02 04 34 12 00 10 23 45 67 AB CD EF 1E
```

| Байты | Значение | Разбор |
|-------|----------|--------|
| `57` | 87 | заряд 87% |
| `18` | 24 | 24 °C |
| `02 04` | вода, модель 4 | СВТ-15, тариф 1 |
| `34 12 00` | 0x001234 | серийный номер 4660 |
| `10` | старшая тетрада 1, младшая 0 | |
| `23 45 67` | первое = 0x1234567 = 19 088 743 | тариф 1: 19 088,743 м³ |
| `AB CD EF` | второе = 0x0ABCDEF = 11 259 375 | тариф 2: 11 259,375 м³ |
| `1E` | 30 | прошивка 3.0 |

### МИР С-01, версия 0

Пакет с адреса `B0:01:03:00:00:2A`:

| Байты | Значение | Разбор |
|-------|----------|--------|
| `00` | версия 0 | суммарная активная энергия |
| `03 01` | электричество, модель 1 | МИР С-01 |

## Что неизвестно

- **Байты 1 и 2 в версии 1** (кроме младшей тетрады байта 2): приложение их не
  использует. Байт 1, по наблюдениям, — счётчик пакетов.
- **Флаги в байте 0**, кроме `0x80` и `0x04`.
- **Зашифрованные пакеты с адресов `B1`**: расшифровываются только на сервере.
- **Порядок линейных напряжений в пакете версии 34.** Приложение из-за ошибки
  записывает все три значения под одним именем (`Uca`), так что последнее
  затирает предыдущие. В переводах приложения есть подписи `Uab` и `Uca`.
  Порядок AB, BC, CA предположен по аналогии с фазными напряжениями.
- **Единицы мощности** (версии 48 и 49) взяты из подписей приложения (Вт, вар,
  В·А). На реальном электросчётчике они не проверены.
- **Год в пакетах истории** (версия 8) и **причина перезагрузки** WiFi box.
- **Служебный обмен с WiFi box** (версии 11 и 12).
- **Электросчётчики, теплосчётчики, пакеты версий 5, 8 и 9** на реальных
  устройствах не проверены. Если у вас такой счётчик, пришлите пакеты в
  [issue](https://github.com/raxers/elehant_water/issues).
